# backcheck

Чекер лаб курса «Backend-разработка». Отправляет запросы к вашему сервису и по каждому пункту чек-листа показывает, работает он или нет. Язык и фреймворк не важны.

## Установка

Нужен Python 3.10 или новее.

```bash
pipx install git+https://github.com/bozhedom/backcheck@v1
```

Если pipx нет:

```bash
pip install --user git+https://github.com/bozhedom/backcheck@v1
```

Проверить: `backcheck --version`. Если команда не находится, запускать так: `python -m backcheck`.

Обновить: `pipx reinstall backcheck`.

## Запуск

1. Запустить свой сервис.
2. Заполнить `contract.json` в корне репозитория. Что в него писать, сказано в задании каждой лабы.
3. В корне репозитория выполнить:

```bash
backcheck --lab 1            # пункты лабы 1
backcheck --lab 1 --stars    # пункты и звёздочки
```

Ещё флаги:

| Флаг | Что делает |
| --- | --- |
| `--only 3` | Проверить только пункт 3 |
| `--all` | Проверить все лабы с 1 по N |
| `-v` | Показать каждый запрос и ответ |
| `--url URL` | Другой адрес сервиса |

## Что значат значки

| Значок | Значение |
| --- | --- |
| ✓ | Работает |
| ✗ | Не работает, рядом написано почему |
| ? | Чекер это не проверяет, показывается на сдаче |
| ⚠ | Предупреждение, на баллы не влияет |

Пример:

```
  6  Плохие запросы: 400, сервер жив
      ✓ битый JSON: 400
      ✓ пустое title: 400
      итог: ✓ засчитано

━━ Итог ━━
Лаба 1: база 5/6 + 1 проверяется на сдаче
```

## Что проверяется

| Лаба | Чекер проверяет | Показывается на сдаче |
| --- | --- | --- |
| 1 | `/health`, создание, список, получение по id, обновление, удаление, ответы 400 и 404, README, `requests.http`, файл зависимостей | Раздел «как запустить», строка лога |
| 2 | Вторая сущность, SQL-инъекция, `.env` не в git, ER-диаграмма, индекс в EXPLAIN, поиск, правило 409, статистика | Перезапуск без Docker, миграции, транзакция |
| 3 | Регистрация, 401, 403, `/auth/me`, автор записи, JWT, админ, 429 | Хэш пароля в базе |
| 4 | CORS, заголовки безопасности, cookie и CSRF, SSE | Работа страницы в браузере |
| 5 | Dockerfile, `docker compose up`, volume, `.env`, второй сервис и 503, логи, прокси, кэш, брокер, HTTPS | Тесты в CI, деплой с телефона |

## Вопросы к лабе

```bash
backcheck ask --lab 1
```

Выдаёт случайный вопрос из списка в задании лабы.

## Разбор JWT

```bash
backcheck jwt <токен>
```

Показывает, что внутри токена и когда он истекает.

## Лаба 5 в GitHub Actions

Файл `.github/workflows/backcheck.yml` в репозитории проекта:

```yaml
name: backcheck
on:
  pull_request:
  workflow_dispatch:
jobs:
  backcheck:
    uses: bozhedom/backcheck/.github/workflows/lab5.yml@v1
```

На каждом PR GitHub поднимает проект через `docker compose` и запускает чекер по всем лабам.
